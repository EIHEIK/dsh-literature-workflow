# 测试与恢复说明

## 测试层次

1. Node host 合约：工具注册、skills provider、实际 session 身份要求、API／归档开关。
2. Python 机制：SQLite 去重和并发领取、旧租约拒绝、源范围完整性、审查登记及当前候选绑定、证据哈希。
3. 文件与崩溃：真实子进程调用 publish 后在提交事务前退出；由新调用恢复并核验文件。另测同一窗口损坏文件，必须拒绝发布。
4. API 代理：假上游响应的 usage、请求上限、截断和未知消费记录，不请求真实 API。
5. worker：真实离线子进程扮演引擎，完成产物收集与待审组合，不声明真实翻译质量。
6. Zotero：假服务模拟远端已提交但响应丢失，以及提交结果未知，验证不重复导入。
7. DSH 实机：安装后的工具／skill 发现、配置、真实 API 试译、真实独立审查及 Zotero 写回另行记录。

## 恢复策略

- worker 心跳约 5 秒，租约 300 秒；活租约禁止重启。取消通过失效 generation/lease 使 worker 停止自己的引擎进程。硬杀 worker 可能留下一个旧引擎；原代理随 worker 消失，不能继续得到真实 API Key；检查旧 PID 后再重启。
- 工具或宿主退出不等于已终止后台 worker。先 status/resume，不能盲目提交。
- 发布目录缺文件可从同一当前验收候选补齐；已有文件字节不符会拒绝覆盖和恢复，需保留坏文件诊断后显式修复。
- 归档 intent 和回执落在作业 archive 子目录，先于网络调用落盘。恢复查询父条目中带候选身份的附件并计算本地文件哈希。
- intent 存在但无可验证附件属于“不知道是否已提交”；停止该附件，检查 Zotero、调用结果与日志。不能把“未查到”直接认定为“未写入”。人工确认确实未导入时备份相应 intent 后移出活动位置，再执行 archive；这不是自动重试流程。
- 旧版已发布作业不可直接 stage；使用 revise + 固定 revision 标签，保留全部历史文件。

## 当前界限

验收协议校验文件身份、覆盖和审查角色，不是科学正确性的数学证明，也不防拥有本机写权限的人直接篡改整个数据库。API 出站发出后中断可能已计费但没返回 usage；记录未知，不记零。业务提交幂等不代表外部模型恰好调用一次。

页面 mapping 的默认连续映射仅用于引擎输出页数与声明源页数相符的情况，仍必须在独立审查中逐页验证。源页数不等、复杂续页或页序变化不能猜测。
