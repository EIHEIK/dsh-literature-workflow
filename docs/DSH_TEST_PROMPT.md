# 发给 DSH 的安装与后台接入提示词

请安装或更新 EIHEIK/dsh-literature-workflow 的 0.2.0-beta.1 测试版，优先使用GitHub Release的tgz。核对当前实际使用的profile，先备份原插件配置，保留原文、旧译本、批注及数据库。

默认使用 mode: service，只将可信安装器生成的 dsh-adapter.json 路径填入 controllerConfig。该文件仅供插件读取，不把其内容、完整service.json或API Key粘贴到聊天。不要自行启动Python、Docker、旧worker，或切回legacy。安装插件不会自动安装完整后台；缺少后台时列出缺项，按安装说明处理。

1. 读取随包 dsh-literature-batch skill，确认 literature_workflow 工具真正注册。调用 get_capabilities 检查连接及能力，不能只凭模块可导入就宣称实机通过。
2. 若已有我授权并启动的批次，直接用已知批次ID查询 get_status 和带游标的 read_events，复用同一任务，不重新准备或初译。不从磁盘猜测批次或读取维护凭据。
3. 新批次只取我指定的Zotero条目或分类，先 refresh_index、get_index_status，再 prepare_batch。保留稳定requestId，报告缺全文、歧义及已有译本排除项，不扩大到整个库。
4. 只有当前批次已经确认且 startAllowed=true 才能 start_batch。一般生产、受控试点、精确原清单继续分别检查对应就绪状态；DSH不能自己签发收据或提高预算。已有授权不重复申请，尚缺授权交给可信宿主处理；Dot暂缓时不以Dot在线为前提。
5. 由固定后台完成背景语料、独立DeepSeek API翻译、正常字号排版、中文/左右双语PDF、全页独立复核、最多两轮返修及重新验收。保留原图、数据、公式及源物理页码；表格文字译成中文，图中英文提供中文对应说明。不能用未审候选或部分负面检查制造通过。
6. 超时、失联或响应丢失时先查询同一任务、容器和费用状态，不盲目重发。保留未知消费、历史费用和已付费结果。单篇预算或质量停止后保留问题包，继续清单其他论文；不自动调用GPT修复，不加第三轮，不涨预算。
7. 只有 get_delivery 返回的当前已验收PDF可以交付。Zotero回挂须对应原父条目且两份文件哈希均一致；未接通写入通道则明确待归档，不能假报成功或反复申请权限。丢失回挂响应先对账，不重复导入。
8. 最后简报真实安装版本、原清单范围、执行/待处理数量、实际费用依据、合格输出、问题包及归档状态。程序或模拟测试与真实全文验收分开报告。正常后台运行只低频查询，发生完成、公共故障、预算停止或需用户决定时及时说明。

本版本仍为测试版。发现公共实现错误应在隔离夹具中修复并回归，保留原始证据；不能修改原报告、删除检查或放宽要求来凑PASS。
