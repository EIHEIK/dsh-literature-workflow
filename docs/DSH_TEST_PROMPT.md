# 发给 DSH 的安装与测试指令

请安装并测试 EIHEIK/dsh-literature-workflow 的当前 RC，优先使用 GitHub Release 的 tgz。确认我的实际 profile，不创建一个没有使用的 profile。保留已有插件配置、原文和旧译本，不修改旧工作流数据库。

1. 阅读 README 和三个随包 skills，确认工具及 skills 真正注册。先 doctor；配置专用 Python/PyMuPDF、固定版本 pdf2zh_next，记录实际版本和缺项。不要把“能导入模块”当实机验收。
2. API Key 仅从环境或受控配置取得，不让我把 key 发到聊天。先完成无需真实模型的测试；API 请求及 Zotero 写开关默认关闭，确认本次试点已授权后开启所需项。
3. 从我指定的 Zotero 论文选择 2–3 个含公式和图表的源页；没有选择桥时让我指定分类或条目，不能猜当前选中。展示源文件和源页范围，创建一份任务后 start，使用 status 跟踪，不重复创建。
4. 核对输出的公式左端、等号、上下标、表格文字和数据、中文图内标签对应及左右源页映射。缺项修订 mono 或 supplements 后 stage。对每次新候选重新独立复核；不降低要求凑 PASS。
5. 使用真实独立 Harness 会话 review_begin，实际读取原文、中文及双语所有页面后填写报告，review_submit。没有该会话能力则保持待审，不编造 reviewerId。
6. 测试失败与恢复：取消后旧 worker 不应写回；未审候选不得发布；候选变化后旧报告无效；已有发布文件损坏时恢复应拒绝。用隔离夹具做这些破坏性测试，不改真实论文产物。
7. 我已选择验收后自动回挂译本。只有 accept/publish 真正通过，才 archive 到对应原父条目；回读两个附件、父条目和文件哈希。仅一个附件成功或响应丢失时先对账，不能重复导入。源页试点应明确标为部分译本，不冒充全文。
8. 报告安装版本、离线测试、真实请求数与 usage、实际费用依据、输出路径、审查身份、剩余缺陷、归档收据以及建议并发和预算。没有真实测试的项目单列，不自动扩大到全库。

遇到实现问题，请在该插件仓库修复并增加对应回归，保持已授权范围，不通过删检查或改报告状态制造成功。
