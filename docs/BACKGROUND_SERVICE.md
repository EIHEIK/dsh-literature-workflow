# 本地后台接入与当前验证边界

当前是未发布的独立后台实现。新安装默认禁止付费作业；本机已按冻结清单与累计预算启用受控真实试点，尚未授予正式生产就绪。服务存在和索引通过不能代替实际模型及译文验收。固定安装、登录启动和回滚见 [安装恢复手册](INSTALLATION_RECOVERY.md)。

**当前部署：Dot暂缓，GPT-6.1 Sol接替必要监督。** 固定安装已连通Codex角色客户端并记录实际档位；下文Dot elicitation只描述保留组件。已授权批次绑定真实用户指令与冻结摘要，不重复申请启动确认；通用流程见[工作流](WORKFLOW.md)。

## 角色与配置

可信部署入口为 `runtime/service_main.py`。`provision --config <私有配置> --data <独立数据目录>` 创建一次配置，不覆盖旧配置或保存 API key。`run --config <私有配置>` 运行唯一后台；安装器应以隐藏进程启动，不能由模型任意构造 shell。

服务首次启动后固化 127.0.0.1 的端口。`export-adapters --config <私有配置>` 生成同目录角色文件：

- `dsh-adapter.json`：仅 URL 与 DSH 角色凭据。插件配置 `mode=service`、`controllerConfig=<此文件>`。
- `dot-adapter.json`：URL、Dot 角色、宿主确认角色和本地会话证据目录，仅供受信任 stdio MCP 适配器。它不是可以发给模型的资料。
- `codex-adapter.json`：URL、Codex角色和本地会话证据目录。当前启用此通道，真实宿主型号必须为GPT-6.1 Sol，档位记录实际选择。

完整 `service.json` 另含维护凭据，不能作为 DSH 的配置。API key 仅由后台环境读取，容器、插件工具参数和公共仓库不接收 key。以上私有文件均不进发布包。

DSH Node 适配器拒绝外部地址、重定向和完整服务配置，没有 Python/旧 worker 自动回退。`legacy` 为保留历史工具的显式兼容模式；不应用于新工作流验收。

## 索引到批次

原生提取当前使用`native-block-order-v2`，按文字块保留双栏段落顺序。缓存按版本隔离，旧提取与历史收据保留；新背景检索只使用当前提取版本。它不等于OCR，缺失符号和负号仍以原文图像为依据。原15篇清单已完成此版本的索引更新。

1. `get_capabilities`（保留的Dot入口为`preflight`）核对连接与能力。当前Codex操作核对实际本地GPT-6.1 Sol宿主；Dot暂缓，不再用其失败阻塞当前队列。
2. `refresh_index` 传 `scope={kind:items|collection,keys:[...]}` 和稳定 `requestId`，范围只限个人 Zotero。调用立即返回持久化 index ID；解析在独立线程和固定隔离容器进行，数据库仍由控制器单线程写入。
3. `get_index_status` 返回逐篇结果。重复 requestId 不创建新任务；同 ID 不允许换范围。当前活动同范围也不能创建第二任务。每次队列最多八个活动刷新；单次 scope 最多100个条目 key 或一个分类。分类按现有分页上限读取。
4. 重启恢复已持久化清单和同一 PDFScanner 启动意图；扫描超时/未知 Docker 状态不授权再启动容器。单篇解析失败明确列出，其他篇仍可继续。没有 OCR 的论文返回无可提取文字，不能假报索引成功。失败项需处理原因后发起新的显式刷新，仍先核对旧容器意图。
5. 用同一 scope 调用 `prepare_batch`，准备阶段重新核对父条目、源文件哈希和解析缓存。已有译本、多个可能源 PDF、缺全文等列入 omissions。刷新索引不自动创建翻译批次。
6. `start_batch`还须通过部署就绪检查及绑定batch/summaryHash的受信任用户确认。正式生产要求真实试点已验收；受控试点另使用限时就绪记录，绑定精确摘要、当前运行代码/镜像、离线链路和当前Sol宿主证据，避免把试点结果当成试点前提。试点仍须15元累计预算和全部质量门禁。当前按已存在的真实用户指令绑定确认，不再重复提问；DSH没有自批准接口。保留Dot组件采用elicitation，但当前不启用。
7. 后台按阶段执行；聊天断开不影响已接受作业。`get_status`/`read_events` 查询进度，`get_delivery` 只返回验收产物。正式运行的完整预算、例外和交付要求见实施计划。

## 语料可信度

原文和参考论文只作为有出处的背景资料。候选术语/记忆按具体 ID、源页、原文引用和实际译文提交独立 API 复核；缺项、拒绝、不确定或候选整体未通过都不能晋升。验收时重新核对私有调用收据后晋升。当前翻译记忆生产端覆盖结构化返修中可定位的段落；未实现引擎全部段落的自动对齐记忆，不宣称已有全量 TM。

## 当前限制

后台、Sol客户端、DSH Node适配和真实批量索引已连通；DSH新插件实机安装仍未验收。固定安装和登录项已落地，实际执行登记命令可恢复后台，尚未做真实注销/重启触发测试。真实首篇有限返修后仍未通过，译稿及当前候选的部分复核响应保留在问题包。维护入口`continue_original_batch.py`可在原用户已授权清单内继续其余论文，核对问题包、无在途/未知费用、精确来源、原预算及离线回归后签发`scopedBatchReady`收据；它不声称一般生产已就绪。该路径已真实启动其余14篇。Zotero10官方桥接仅完成源码与合成测试，仍需一次明确授权，真实回挂为零。详见[验证边界](VALIDATION.md)。

首篇真实归档完成后，维护入口`scripts/activate_verified_batch.py`默认只读审计；带`--activate`才在核对固定安装、原清单完整不重叠覆盖、预算、原始用户授权、当前接受证据及两份真实Zotero附件哈希后签发生产就绪记录并启动原14篇队列。该入口不授予译文验收、不扩大清单或预算，不暴露为DSH/模型工具。
